# 客户跟进 Skill PRD

## 1. 背景

目标用户是高频使用微信沟通的销售、代理管理和 FAE 场景。

日常痛点主要有 6 类：

1. 客户和代理商消息太多，容易漏掉业务重点、风险和待处理事项。
2. 同时跟进多个客户和项目，容易忘记项目进度、芯片方向和最新结论。
3. 客户或代理商自己选型时，容易出现芯片能力与需求不匹配。
4. 代理商转述需求常常模糊，技术问题需要先归类、再升级、再持续追踪。
5. 每日/每周跟进汇报整理成本高。
6. 冷门 WiFi 音视频项目需要快速判断可做性，并回看是否有类似案例。

## 2. 产品目标

把现有 `wechat-uia-cli` 从“聊天抓取工具”升级成“客户跟进底座”。

它需要完成两层能力：

- 第一层：直接落地到代码里，优先解决每天都在发生的业务整理工作。
- 第二层：基于知识库做规则判断，先用虚拟资料跑通，后续由客户替换真实资料。

## 3. 范围划分

### 第一层：本期直接实现

对应需求 `1 / 2 / 4 / 5`：

- 按客户抓取当天微信聊天
- 按天归档聊天记录
- 生成客户时间轴
- 自动提炼业务摘要、风险、待办、问题
- 建立项目快照
- 建立 issue 跟踪列表
- 自动生成每日报告
- 自动生成周报草稿

### 第二层：本期用虚拟资料实现骨架

对应需求 `3 / 6`：

- 芯片选型规则校验
- 相似项目案例召回
- 冷门 WiFi 音视频项目的初步可行性提示

当前通过虚拟知识库演示流程，后续由客户提供真实资料替换：

- `knowledge/chip_catalog.json`
- `knowledge/project_cases.json`

若未提供真实文件，系统自动回退到：

- `knowledge/chip_catalog.virtual.json`
- `knowledge/project_cases.virtual.json`

## 4. 非目标

这套方案不是数据库级真值系统，也不是法务/审计归档系统。

当前明确不做：

- 逐条消息的发送者精准归因
- 每条消息的精确时间恢复
- 代替人工做最终商务判断或最终技术承诺
- 在没有知识库命中的前提下给出高置信度选型结论

## 5. 核心业务流程

### 日常运行流程

1. 维护 `config/customers.yaml`
2. 每天运行 `customer-followup --since today`
3. 自动抓取客户聊天
4. 沉淀日档 JSON
5. 重建客户时间轴
6. 刷新项目档案
7. 刷新 issue 列表
8. 输出每日报告和周报
9. 再由上层智能体基于这些结构化结果继续生成高质量汇报/建议

### 输出文件

## 6. 代码层与大模型层职责边界

### 代码可以稳定做的

- 通过 UIA 按客户抓取聊天记录
- 按日归档消息和元数据
- 规则提炼需求、商务、技术、风险、紧急事项
- 维护客户时间轴
- 维护项目快照
- 维护 issue 列表和历史快照
- 生成日报/周报草稿
- 在知识库命中时做规则化芯片能力校验
- 在知识库命中时做相似案例召回

### 调用 skill 的大模型更适合做的

- 把结构化结果改写成更自然、更像销售助理的报告
- 对模糊需求做上下文推理和补全
- 给出下一步沟通策略、回复话术、内部升级建议
- 综合多个客户日报生成管理视角总结
- 在芯片规则命中后做更高层的机会判断和优先级排序

### 关键原则

代码负责“稳定提取、稳定沉淀、稳定产出底稿”。

大模型负责“理解语义、优化表达、辅助判断”。

## 7. 数据输入

### 必填输入

- 微信 PC 版运行环境
- `customers.yaml` 客户配置

### 可选增强输入

- `owner`
- `chip_focus`
- `project_hints`
- `knowledge-dir`

### 真实知识库替换要求

芯片知识库至少建议包含：

- 型号
- 别名
- 家族
- 能力标签
- 适配场景
- 不适配场景
- 注意事项

案例知识库至少建议包含：

- 案例标题
- 场景标签
- 使用芯片
- 结果结论
- 关注点
- 推荐/不推荐条件

## 8. 关键判断逻辑

### 第一层

- 聊天摘要：规则提取需求、商务、技术、风险、日程推进
- 项目快照：从客户 hints、场景推断和对话摘录构建
- issue 跟踪：对紧急项、风险项、技术项、待确认问题持续累计
- 日报/周报：围绕“进展、风险、下一步”自动生成

### 第二层

- 芯片选型：根据识别到的需求能力与芯片能力表做匹配
- 相似案例：根据场景标签和芯片命中召回
- 可行性提示：输出“可评估 / 有风险 / 待补资料”

## 9. 成功标准

### 第一层成功标准

- 每天一条命令能稳定更新客户档案
- 能让用户快速看到“今天谁有进展、谁有风险、谁要跟进”
- 日报和周报不再需要从零手工整理

### 第二层成功标准

- 在真实知识库接入后，能对常见选型问题给出规则化预警
- 对冷门项目能给出至少一层“类似案例/类似场景”提示

## 10. 风险与限制

- UIA 仍存在分页启发式和时间粒度不足的问题
- 发送者身份仍不可得
- 富媒体消息会被简化
- 没有真实知识库时，第二层结论仅作演示和流程占位

详细限制见：

- `docs/known-limitations.md`

## 11. 本期落地结论

本期实现策略：

- 第一层直接代码落地
- 第二层用虚拟知识库跑通链路
- 文档里明确标注哪些结果来自代码规则，哪些应该交给上层大模型继续完成
